Abstract

Learning to Select (Wu et al., 2026) shows that a small query-only predictor can pick which coordinates of a dense embedding a query should use, keeping document vectors and the index untouched. Such a selector is trained for one retrieval environment. HyperDIME-Qwen asks whether the best selector changes across environments (H1), whether statistics of the embedding space explain that change (H2), and whether a hypernetwork can turn those statistics into selector parameters for an unseen environment (H3). The project is gated so each link can be refuted before the next is built. The first experiment, the F0 spike, tested H1 on five BEIR datasets with 3 seeds per selector. Its pre-registered rule returned H1 supported, but two of the three criteria passed exactly at threshold. All of the gain came from scifact and nfcorpus. On those two sets 63.7% and 99.9% of eval positives are also training positives; on fiqa and arguana none are. We read F0 as a preliminary signal that does not yet settle Gate G2. Section 8 lists the controls needed first.

1 Introduction

Dense retrievers score a query against documents with an inner product over all D coordinates. Not every coordinate helps every query. Query-aware dimension selection keeps, for each query, the k coordinates most useful for ranking and zeroes the rest on the query side only, so the document index is unchanged.

Learning to Select trains a linear layer f(eq) = log-softmax(W eq + b) to imitate an oracle importance distribution built from labelled positives and hard negatives. The selector is trained per dataset. A new corpus, query population or instruction means new labels and a new selector.

HyperDIME-Qwen fixes the encoder, Qwen3-Embedding-0.6B at full dimension, so the 1024 coordinates keep a stable identity. It then studies how the best selector depends on the environment T = (corpus, query distribution, instruction, frozen encoder). The project tests a causal chain one link at a time:

distribution shift → embedding geometry shift → optimal selector shift → hypernetwork adaptation

HypothesisIf it fails
H1Selector shift: the optimal selector for the same Qwen model changes systematically across environmentsBuild one universal selector; no hypernetwork
H2Geometry explains the shift: space statistics predict part of the changeIterate on the space descriptor
H3A Hyper Head maps environment statistics to selector parameters that beat a global selector on unseen environmentsThe parameterization or training is the problem

The repository began as Hyper-Mask-Net, which generated a mask network per query from Qwen token states. On SciFact it beat random masks but not the full embedding or the linear Learning-to-Select selector at 30% of dimensions. It was restarted on 2026-07-21 with the environment-conditioned design (ADR-0001).

2 Proposed method

2.1 Two paths

Offline, once per environment. A space descriptor summarizes how the environment uses each coordinate. A space encoder and a Hyper Head turn it into selector parameters θT, which are stored.

flowchart LR
  C["Corpus + optional calibration queries"] --> E["Frozen Qwen embeddings"]
  E --> R["Space descriptor R_T (1024 × h)"]
  R --> G["Space encoder G_ψ"]
  G --> H["Hyper Head H_φ"]
  H --> P["θ_T = W_0 + A_T B_Tᵀ, b_0 + Δb_T"]

Online, per query. The selector scores dimensions, a policy keeps the top k, and exact search runs over unchanged documents: e′q = eq ⊙ mq, score(q, d) = e′qᵀed. The masked query is not re-normalized.

flowchart LR
  Q["query + instruction"] --> QE["e_q (1024)"] --> S["selector f_θT"] --> P["top-k policy"] --> M["mask m_q"]
  QE --> X["e_q ⊙ m_q"]
  M --> X --> RET["exact search, documents unchanged"]

3 Research protocol

Work proceeds through five gates. Each gate decision is recorded as an architecture decision record (ADR), and a failed gate stops the project from adding complexity.

GatePasses whenDecided byStatus
G1Valid baseline: Learning-to-Select converges, masking is correct, exact retrieval ranks as expectedE0not started
G2H1 supported: selectors differ beyond seed noise and transfer degrades retrievalE1 / M4preliminary signal (F0)
G3H2 supported: descriptors predict selector or transfer properties above a trivial baselineE2 / M5.4not started
G4H3 supported: the hypernetwork narrows the global vs per-domain gap on unseen environmentsE3not started
G5Offline adaptation is amortizable; online overhead keeps the dimension-reduction benefitE6 / M12.2not started

Leakage rules. Splits exist at two levels. Environments are divided into meta-train, meta-validation and meta-test; queries into train, validation and test. Test labels never reach training, negative mining, oracle targets, descriptors or normalization. P0 and P1 code paths may not read labels at all.

Reporting rules. Metrics use exact scoring (nDCG@10, MRR@10/100, Recall@100, linear gains as in trec_eval). Every table includes the full 1024-dimension embedding and MRL prefix truncation (risk R5), plus a global multi-domain selector trained on the same labels (risk R6). Significance uses paired per-query tests with multiple-comparison correction and confidence intervals. Offline adaptation cost is reported separately from per-query cost. Every table is generated from result files that carry a run manifest.

Full corpora are used. Datasets without a train split (arguana, scidocs) use a fixed 50/50 split of their judged test queries, and 10% of each training pool becomes validation. Train and evaluation queries are disjoint in every environment, and evaluation labels never reach training.

4.2 Embeddings

Qwen/Qwen3-Embedding-0.6B (revision 97b0c614), bfloat16, texts cut to 512 tokens, last-token pooling, L2-normalized, 1024 dimensions. Queries carry each dataset's Qwen3 evaluation instruction as Instruct: …\nQuery:…; documents have no prefix.

4.3 Oracle targets

For each labelled query the target is a distribution over dimensions:

πq = softmax( eq ⊙ (p̄ − n̄) / τ )

Here p̄ is the mean of the positive documents weighted by gain 2rel − 1, and n̄ is the mean of 64 negatives sampled with replacement from the query's top-1000 non-positive documents under the full embedding. This follows the official Learning-to-Select label generation (ADR-0002).

4.4 Selector and training

The selector is one 1024→1024 linear layer with log-softmax, trained on KL(πq ‖ π̂q) with AdamW (lr 0.0001, weight decay 0.0001), batch 32 and cosine decay over a fixed epoch budget. The state with the lowest validation KL is kept. Temperature and epochs are chosen per environment on validation nDCG@10 at k = 307 from τ ∈ {0.005, 0.01, 0.02, 0.05, 0.1, 0.2} × epochs ∈ {10, 50, 200}, using seed 0 and training labels only. Each environment then gets 3 selectors (seeds 0, 1, 2). The global selector is trained on the union of all environments' training labels, with its epoch count tuned on mean validation nDCG@10.

4.5 Systems compared

Evaluation uses exact scoring at k ∈ {128, 256, 307, 512} (headline k = 307, 30% of dimensions), excluding a document whose ID equals the query ID, as BEIR does for ArguAna. Per-query metrics are averaged over seeds before testing.

4.6 Mask analysis and statistics

All 2471 evaluation queries form one unlabelled battery. Each selector's top-307 masks on the battery give overlap@k within an environment (across seeds) and across environments. Mean importance vectors are compared with Jensen–Shannon divergence and Spearman rank correlation. Paired differences use a two-sided sign-flip randomization test (10,000 permutations), a percentile bootstrap 95% CI (10,000 resamples over queries) and Holm correction within each family (α = 0.05).

4.7 Verdict rule

H1 is supported only if all three criteria hold at k = 307, on nDCG@10:

Criterion
C1Transferred selectors lose significantly to the in-domain selector on ≥ half of the ordered pairs
C2Cross-environment mask overlap@k is significantly below cross-seed overlap
C3In-domain beats the global selector significantly on ≥ 2 of 5 environments

C3 is the practical test: without a gap between per-domain and global selectors there is nothing for a hypernetwork to recover, even if H1 is technically true.

7 Discussion

The verdict is correct under the rule as written, but the evidence is thin. The main threats to validity:

  1. Document overlap drives the gain. Queries are split, documents are not. Headroom appears where eval positives were seen as training positives (scifact 63.7%, nfcorpus 99.9%) and vanishes where they were not (fiqa, arguana 0%). A selector may learn which corpus regions are relevant rather than how the domain uses coordinates. This uses legitimate training labels, so it is not leakage. It is a confound for H1, and for the hypernetwork, which will not see labels on new environments. scidocs (20.8% overlap, no gain) shows overlap is not sufficient on its own.
  2. Thresholds. C1 passes with 10/20; 8 of those losses land on scifact and nfcorpus. C3 passes with exactly two environments.
  3. Instruction shift. A transferred selector sees queries carrying another dataset's instruction prefix, so part of the measured transfer loss may be instruction shift rather than corpus shift.
  4. Seed noise. For nfcorpus, arguana, scidocs, seeds agree with each other less than with some other environment. Jensen–Shannon divergence stays below 0.0002, so mean importance is close to uniform. C2's CI is tight because the bootstrap resamples the 2471 battery queries only, not seeds or environment pairs.
  5. Training. 5 of 5 epoch choices and 4 of 5 temperatures sit on a grid edge, and 12 of 15 training runs kept a state from their last three epochs, so validation KL was mostly still falling when training stopped. Yet the grid picked the shortest budget for three environments, where longer training lowered validation nDCG. KL to the oracle and ranking quality may not be well aligned.
  6. Prefix is strong. Outside scifact and nfcorpus the selectors do not beat MRL prefix truncation. This is risk R5 in practice.

An earlier F0 run at commit 94bbefc returned "not supported". Its selectors did not beat random masks on four environments, which ADR-0002 traced to early stopping and label generation that differed from the official recipe. Fixing the recipe flipped the verdict, which shows how sensitive H1 is to training choices.

Recommended before Gate G2

  1. Evaluate scifact and nfcorpus on eval queries whose positives never occur in training, or split the corpus as well as the queries. If headroom survives, H1 stands on firmer ground.
  2. Control instruction shift: encode transferred queries with a shared instruction, or measure transfer with the instruction swapped.
  3. Widen the grid (below 10 and above 200 epochs, below τ = 0.005) and check the KL–nDCG mismatch.
  4. Bootstrap C2 over seeds and environment pairs as well as queries.
  5. Add environments with real train splits and little document overlap before investing in phases D–E.
  6. Commit the F0 report on exp/F0-selector-shift and record the decision in an ADR, per the workflow.
