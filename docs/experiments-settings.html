HyperDIME-Qwen · experiment methods

Settings at every experiment stage

A configuration and provenance guide to the completed selector experiments. It describes what enters each stage, the settings that control it, and how a choice is made.

Scope. E0, E1, P1, and S1–S3 are reported in the experiment registry. The figures below are settings, not newly computed results. Source links point to the code, configuration, protocols, or generated reports that establish each setting. View the experiment curves by retained dimensions.

Invariant. Qwen3-Embedding-0.6B is frozen at 1024 dimensions. A selector masks only the query; the query is not normalized again, and document vectors and the index stay fixed.

01

Prepare data

hyperdime prepare-data defines each retrieval environment and keeps training, validation, and test judgments separate.

EnvironmentsBEIR SciFact, NFCorpus, and MS MARCO. MS MARCO uses its full passage corpus; TREC DL 2019, DL 2020, and DL-HARD are extra evaluation query sets.
SplitsTraining queries split 90% / 10% into train and validation. Split seed 0. MS MARCO training queries capped at a seeded sample of 50,000.
Access ruleTrain labels build targets and negative pools; validation labels choose cells and checkpoints; test and TREC judgments score final rankings only.
Inputs / outputPinned source and qrels revisions, environment instruction, split settings → prepared environment with a run manifest.

Sources: SciFact, NFCorpus, MS MARCO, pinned environment registry, split implementation, protocols.

02

Embed queries and documents

hyperdime embed computes reusable vectors once per environment.

ModelQwen/Qwen3-Embedding-0.6B, revision 97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3; frozen; D=1024.
EncodingLast-token pooling, L2 normalization, maximum input length 512. Queries use Instruct: {instruction}\nQuery:{query}; documents have no instruction prefix.
Precision and storageModel config requests bfloat16 compute on GPU, while CPU uses float32; cached embeddings use float16 storage. Run settings request auto device.
CLI defaultsLocal backend, batch size 128, shard size 65,536; a vLLM backend is also available. Actual backend, dtype, role, and instruction are recorded with the embeddings.

Sources: model config, run config, encoder settings, embed CLI.

03

Mine hard negatives

hyperdime mine-negatives prepares the non-relevant examples used by selector training.

Candidate searchExact full-embedding ranking; inspect the top 1,000 documents for each train or validation query.
PoolSample 64 documents per query from candidates after excluding judged positives and the query's own document ID where applicable; seed 0.
IsolationOnly train and validation queries are processed. Test judgments are not loaded for negative mining.

Sources: negative pool implementation, CLI defaults, ADR-0002.

04

Train baseline selectors E0

train-selector --recipe official | candidates | seeded fits the Learning-to-Select (L2S) map to oracle importance. train-global fits a shared selector across environments.

Target and modelOracle target from e_q ⊙ (p − n), softened by temperature. The selector is a linear 1024 × 1024 map plus bias, optimized by KL divergence to the target.
OptimizerAdamW; learning rate 1e-4, weight decay 1e-4, batch size 32. Default schedule is cosine; the validation-stopped family uses a constant rate and patience 5.
Official gridTemperatures .005, .01, .02, .05, .1, .2 × epochs 10, 50, 200 (18 cells).
Candidate gridWide grid: 10 temperatures from .001 to 1 × epochs 3, 10, 50, 200, 500. Plus validation-stopped and global-regularized families.
Choice and seedsChoose on validation nDCG@10 at k=307, using exact full-corpus search. E1 uses the wide-grid family with seeds 0, 1, 2.

Sources: baseline grids and selection, trainer defaults, E0 report, E1 report.

05

Measure selector shift E1

hyperdime transfer-matrix applies each trained environment selector to each environment, then compares both retrieval and chosen dimensions.

Training cellsValidation-chosen wide-grid cells: MS MARCO t=.5, 200 epochs; NFCorpus t=.2, 500 epochs; SciFact t=.1, 500 epochs. Three independently trained seeds per environment.
EvaluationExact scoring across the full corpus, masks at each 10% budget, in-domain and cross-environment transfer. Compare overlap of top dimensions and importance profiles against within-environment seed variation.
StatisticsAverage the three selector seed scores per query before paired tests. Test qrels appear only during evaluation.

Sources: E1 report and selected cells, generated transfer table, G2 decision.

06

Probe geometry and train the selector track P1 · S1–S3

P1 measures what document geometry alone can do. S1–S3 then train query selectors with a masked retrieval objective.

P1 scoreKeep dimensions by q_d² × Var(x_d), with document variance computed without labels. Also report covariance participation ratio and energy in the mean.
S1Linear selector trained with relaxed top-k masking and a retrieval loss over positives, hard negatives, and in-batch negatives. Initialization is scratch or the E1 L2S selector.
S2Add the fixed prior log(q_d² × Var(x_d) + ε) to the learned linear score; begin with the linear map at zero.
S3As S2, with one learned scalar on the geometric prior, initialized to 1.
GridFixed k=307 or a budget drawn from the 10%–90% set; learning rates 1e-4, 1e-3; score temperatures .02, .05; final mask temperatures .1, .02. S1 has 32 cells; S2 and S3 have 16 each.
Training defaults20,000 steps, AdamW batch size 32, weight decay 1e-4; mask temperature decays geometrically from 1; evaluate every 1,000 steps.
ChoiceSeed-0 grids are chosen by exact full-corpus validation nDCG@10 averaged over nine budgets, subject to final soft mass ≥ .9. Selected cells are retrained with seeds 0, 1, 2; each run keeps its best validation rerank checkpoint.

07

Compare on held-out queries

hyperdime compare-selectors --experiment S1 | S2 | S3 evaluates selected methods on the same held-out query sets.

Mask and scoringKeep the query's top-k dimensions; zero the others. Do not re-normalize. Rank unchanged document embeddings by exact inner product over the full corpus; FAISS is reserved for deployment analysis.
Budgetsk=102, 204, 307, 409, 512, 614, 716, 819, 921 (10%–90% of 1024, floored); 1024 is the full-vector reference.
ComparisonsFull dimensions, MRL prefix, random, global importance, L2S, corpus variance, and the experiment's trained selector where applicable.
SummaryMean per-query nDCG@10 across the nine masked budgets. Seed scores are averaged per query before statistical testing.

Sources: generated overview, comparison command, metric and leakage rules.

08

Generate reports and decisions

hyperdime report <experiment> reads result files and manifests; hyperdime decide <gate> records the gate criteria and evidence.

Reported measuresPrimary retrieval: nDCG@10, MRR@10, MRR@100, Recall@100. Selection: retained dimensions, overlap, importance entropy, oracle KL, and usage frequency where relevant.
UncertaintyPaired per-query tests and confidence intervals; Holm correction for multiple comparisons. Reports state the protocol and identify contributing runs.
ProvenanceEvery run artifact has a manifest with command, configuration hash, source revision, seed, device, dtype, timestamps, and file hashes. Report tables are generated from result files; no experiment number is edited by hand.
Cost reportingOffline adaptation is kept separate from online query encoding, selector, mask, and search costs.

Sources: reporting protocol, manifest contract, overview report, registry.
