Models and training

Every method below keeps the frozen Qwen3-Embedding-0.6B encoder and its 1,024-dimensional embeddings. A method only chooses which query coordinates to keep. Per query it scores the 1,024 dimensions, keeps the top k as a hard 0/1 mask, and ranks the whole corpus by the inner product of the masked query with each unchanged document embedding. The masked query is not re-normalized, and documents and the index are never touched. Training, tuning, negative mining, and normalization use training and validation judgments only. Test judgments are used only to score the curves in E0–E1 and S1–S4. The P3 experiments read training judgments only.

Shared data. Each environment (SciFact, NFCorpus, MS MARCO) has fixed train, validation, and test query splits. For every training and validation query, 64 hard negatives are sampled with replacement, using a fixed seed, from the top 1,000 non-positive documents of the unmasked ranking. Positives are weighted by the exponential gain 2grade − 1. Each card's run, commit, selected grid cell, and seeds are listed in its linked experiment report.

Reference masks (no training)

prefix · prefix-k
The first k dimensions, as in Matryoshka truncation. The same mask for every query.
random
Seeded uniform scores per query (seed 0), then top k.
global-importance
One ranking for all queries: the mean Learning-to-Select training target of the environment (below), at the environment's tuned temperature.
oracle (E0)
The importance e_q ⊙ (p − n) computed from the judged positives (p) and mined negatives (n) of the query being scored. It reads evaluation labels, so it cannot be deployed and serves only as an upper reference.
variance (P1)
Keeps the k dimensions with the largest q_d² · Var(x_d), where Var(x_d) is the variance of dimension d over the corpus's document embeddings. It uses no judgments and no training: the corpus geometry alone.

Selectors trained toward the oracle distribution (Learning-to-Select)

l2s · l2s:<env>

Model. A linear selector s = W q + b, with W a full 1,024 × 1,024 matrix and a bias, mapping the query embedding to one score per dimension.

Target. For each training or validation query, softmax(e_q ⊙ (p̄ − n̄) / τ), where p̄ is the gain-weighted mean of the positive embeddings and n̄ is the mean of the 64 hard negatives.

Training (ADR-0002, the official recipe). The loss is the KL divergence from the target to softmax(s). The optimizer is AdamW with lr 1e-4, weight decay 1e-4, and batch 32, using cosine decay over a fixed number of epochs. The state with the lowest validation KL is kept, with no early stopping. Temperature τ ∈ {0.005, 0.01, 0.02, 0.05, 0.1, 0.2} and epochs ∈ {10, 50, 200} are chosen per environment on validation nDCG@10 at k = 307, using seed 0.

Where each version appears. E0's l2s is this official checkpoint. In E1 and S1–S4, l2s:<env> is the best cell of the wider grid (τ from 0.001 to 1.0 × epochs ∈ {3, 10, 50, 200, 500}), retrained with seeds 0, 1, 2, with scores averaged per query.

selected (E0)
The best validation cell over four Learning-to-Select families. Ties go to the official recipe. The families are:
  • official: the recipe above.
  • wide-grid: the wider grid described above.
  • val-stopped: a constant learning rate for up to 500 epochs, stopping after 5 epochs without a validation-KL improvement.
  • global-regularized: an L2 pull toward the global selector, with weight ∈ {1e-4, 1e-3, 1e-2, 1e-1}.
global-selector (E1)
One linear selector trained on the union of the three environments' training targets, each at its own official τ, and validated on the union of their validation sets. It is never trained on a test label.
selector:<env> (E1)
The wide-grid Learning-to-Select selector of the named training environment, with seeds 0, 1, 2. It is scored in-domain and transferred unchanged to the other environments' test queries. That transfer is the selector-shift test.

Selectors trained on masked retrieval (S1–S4)

The S1 objective, which S2–S4 reuse.

  • Soft mask. Selector scores are standardized per query to z. A relaxed top-k mask m = sigmoid((z − t) / β) uses a threshold t halfway between the k-th and (k+1)-th score, with no gradient through t. β anneals geometrically from 1 to βend.
  • Loss. The masked query q ⊙ m scores the query's positives, its 64 hard negatives, and the batch's other distinct positives. The loss is a gain-weighted, multi-positive softmax cross-entropy at temperature τs.
  • Optimization. AdamW with weight decay 1e-4, batch 32, and cosine decay over 20,000 steps.
  • Budgets. fixed-307 trains at k = 307 only. multi-budget draws one of the nine 10%–90% budgets per batch.
  • Checkpoint and selection. In S1–S3, each run keeps the checkpoint with the best validation nDCG@10, reranking each validation query's candidate pool and averaging over the nine budgets. Grid cells are chosen with seed 0 by full-corpus validation nDCG@10 averaged over the nine budgets. A cell whose soft mask keeps less than 90% of its mass on the hard top k is rejected. Evaluation always uses the hard top-k mask, and the selected cell is retrained with seeds 0, 1, 2.
retrieval:<env> (S1)
The same linear selector as Learning-to-Select, trained with the objective above instead of KL to the oracle. Grid (32 cells): budget mode {fixed-307, multi-budget} × init {scratch, the L2S checkpoint} × lr {1e-4, 1e-3} × τs {0.02, 0.05} × βend {0.1, 0.02}. On NFCorpus every seed kept its starting checkpoint, so retrieval:nfcorpus is the L2S selector itself.
geometric:<env> (S2)
Scores log(q_d² · Var(x_d) + ε) + (W q + b)_d, where the first term is the fixed corpus-variance prior and W, b start at zero. At step 0 it is exactly variance, and training learns a per-query correction with the S1 objective and grid rules.
weighted:<env> (S3)
S2's selector with one learned scalar a on the prior, starting at 1: a · log(q_d² · Var(x_d) + ε) + (W q + b)_d. Trained like S2.
budget:<env> (S4)
One non-negative prior weight a_k per 10%–90% budget, with the linear map shared by every budget. At step 0 it is variance at every budget. It is trained in multi-budget mode on an 8-cell grid. Every evaluated state, step 0 included, is a candidate, scored by exact full-corpus validation nDCG@10 on a fixed, hashed subset of at most 1,000 validation queries.
weighted-aligned:<env> (S4 control)
S3's single-weight selector retrained on S4's 8 cells with S4's checkpoint rule. It differs from budget only in having one weight instead of one per budget.

P3 masks: privileged diagnostics, nothing trained

P3 measures how far a per-query mask could move rankings when it is built from that query's own training positives. Scoring is exact float64 over every corpus document, with ties going to the lower corpus row. These masks need judgments, so none is a retrieval method and none is a ranking upper bound: they maximize the positives' mean similarity, not nDCG.

shared (P3 ranking) · all-positive oracle (privileged) (P3 oracle vs L2S)
The top k of the gain-weighted mean of q ⊙ d over all of the query's positives. It saw the documents it is scored on.
1-1 · held-out transfer (1-1)
A mask built from one construction positive (q ⊙ d, top k). In the curves here it is scored on all labels, so the construction positive still counts and can inflate the gain. Its effect on the held-out positives of the same query is the primary measure in the P3 ranking report. The 2-2 to 20-20 constructions need more positives, so they cover smaller cohorts and are left off this chart.
L2S (in-sample) (P3 oracle vs L2S)
The official-recipe Learning-to-Select checkpoint for the environment: one seed, with its provenance verified against the inputs read here. It was trained on these very training queries, so its curve shows in-sample fit, not performance on unseen queries.
